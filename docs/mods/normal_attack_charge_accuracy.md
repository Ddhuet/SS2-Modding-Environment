# normal_attack_charge_accuracy

Normal (tap A) attacks get the same accuracy as charge attacks. Definition:
`patches/custom/normal_attack_charge_accuracy.json`, generated by
`translation/tools/make_normal_attack_charge_accuracy.py`. Shipped as
`Patch_Manager/patches/normal_attack_charge_accuracy.ips` (4 records, 17 bytes, against the English ROM).

## How vanilla accuracy works (CN baseline = English ROM addresses)

Player physical hit roll vs a monster (inline in melee `0x0801FC14` at `0x08020192..0x080201D4`;
shared `0x080222B4` for projectiles):

    threshold = floor(125 * (A + 10) / (A + D + 20));  hit if threshold >= rand() % 100

- D: target monster `+0x37A` (literal `0x37A` at `0x0802021C`, `0x080765D4`, `0x08077010`, `0x08077A70`).
- A: attacker actor DEX `+0x42`, **×3 when the attack is a charge attack**.

| Path | Function | Choice of A |
|---|---|---|
| melee | `0x0801FC14` | `actor+0x26 == 2` (tap): `0x0801FCF2` A=DEX; `== 5` (charge): `0x0801FD0C` A=3·DEX → `[sp+0x20]` |
| bow | around `0x08075FEC` | `[sp+0x204] == 0` → `beq` to A=DEX at `0x08076014`; else 3·DEX → `[sp+0x224]` |
| spear | around `0x08076A16` | `[sp+0x214] == 0` → `beq` to `0x08076A38`; else 3·DEX → `[sp+0x234]` |
| knife | around `0x08077438` | `[sp+0x20C] == 0` → `beq` to `0x08077460`; else 3·DEX → `[sp+0x230]` |

**Weapon skill level is not an input to accuracy.** It only unlocks the charge attack (and its
form and damage). Runtime proof: with the axe skill slots forced from 1 to 5 (a diagnostic RAM write), charge A stayed 42.
The CN mod `weapon_skill_hit_rate` (SS2_GBA_HACK) instead adds a new `floor(level·DEX·25%)` term;
this mod does not do that.

Other DEX→hit sites (`0x0802099C`, `0x080780E2`, `0x08078956`) use plain DEX and are not
player→monster attacks; untouched.

## Writes

| Address | Before | After | What |
|---|---|---|---|
| `0x0801FCF2` (14 B) | `mov r0,r8; adds r0,#0x42; movs r4,#0; ldrsh r3,[r0,r4]; str r3,[sp,#0x20]; b 0x080200F0; .hword 0` | `mov r0,r8; movs r4,#0x42; ldrsh r3,[r0,r4]; lsls r0,r3,#1; adds r3,r3,r0; str r3,[sp,#0x20]; b 0x080200F0` | melee tap A = 3·DEX |
| `0x08075FF0` | `beq` (`10d0`) | `nop` (`c046`) | bow |
| `0x08076A1A` | `beq` (`0dd0`) | `nop` | spear |
| `0x0807743C` | `beq` (`10d0`) | `nop` | knife |

Allocations: none. `0x0801FCFE` was the 2-byte alignment pad before the pool at `0x0801FD00`
(no PC-relative load reaches it). The only branch into `0x0801FCF2..0x0801FCFF` is the `beq` at
`0x0801FCE4` to its start. r0/r3/r4 are dead at the join `0x080200F0` (reloaded at
`0x080200F0`/`0x080200F6`/`0x080200FC`), and the new r4 = 0x42 instead of 0 is harmless. The projectile
flags are still reloaded from the stack where used later (e.g. `0x08076A42`).

## Checks

- `mod_conflicts.py --defs patches/custom`: ok (code:4).
- `combine_patch.py` with every official single and every custom mod, pairwise: no overlap.
- `ss2tools build` output `translation/build/ss2-en+normal_attack_charge_accuracy.gba`, SHA-256
  `b07040c0…c4876b`. It differs from the English ROM only in these 17 bytes. The IPS reproduces it exactly.

## Runtime (English vs English+mod)

User state `translation/build/Dragonute_Axe.ss0` (Dragonute, axe, DEX 14, target D 7), visible
input only: UP 25 frames, then A taps or A held 70 frames, breaking at `0x08020192` (A) and `0x080201D4` (result).
Probe script: scratch `probe.py` (replays the state through `smoke_state.open_state`).

| ROM | tap A / threshold | charge A / threshold |
|---|---|---|
| English | 14 / 73 (74% hit) | 42 / 94 (95%) |
| English + mod | **42 / 94** | 42 / 94 |

Status: melee `runtime_verified`; bow/spear/knife `static_verified` only (no Archer/Ninja state yet).
