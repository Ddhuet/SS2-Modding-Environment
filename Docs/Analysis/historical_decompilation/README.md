# Historical Full Decompilation Corpus



This directory contains historical static analysis output without file-by-file explanations, provided for full-text searching, finding candidate functions, and reading pseudocode. It is neither the machine ground truth for the current baseline nor directly compilable source code.

## Sources and Baselines



* **Source:** Source project `rom/ghidra_out/`.


* **Generation Tool:** Ghidra 12.1.3, BinaryLoader, base address `0x08000000`, language `ARM:LE:32:v7`.


* **Historical Analysis ROM:** Legacy baseline with SHA-256 starting with `cedd3b9d...`.


* **Historical Clean Baseline Corresponding to Corpus:** SHA-256 `12c0c32b4e770d0f0d25d237f4cc0a89114ad784d01e6889af998dbe927ea380`.


* **Current SS2_SC Baseline:** SHA-256 `45ac38bb1bfba779592b5c79ce94982cf7c00fda5b3c5b84735e55c77d6fc989`; addresses in the corpus serve only as candidate navigation and must be re-verified against the current ROM for raw bytes and control flow.



Addresses and control flow in historical pseudocode can be used to locate candidates, but cannot be automatically inherited as original bytes, function boundaries, or dynamic conclusions for the current baseline. Before making any modifications, the corresponding range must be re-read from the current baseline, and Thumb/ARM, preimage, branch, ABI, and ownership checks must be performed.

## Contents



* `decompiled/`: Full function pseudocode and indices exported in bulk by Ghidra, totaling 3,775 files.


* `annotated/`: Pseudocode for 13 core functions with manually annotated symbol names.


* `functions.txt`: Historical function entry table.


* `strings.txt`: Historical string identification results.



Items such as `FUN_...`, `DAT_...`, parameter types, local variable names, and function boundaries in these files are largely generated by automated analysis. Just because a name appears specific does not imply it has been manually verified.

## Recommended Usage



1. First check `FUNCTION_INDEX.json` and `STRUCTURE_FIELDS.md` in the parent directory.


2. Use text search in this directory to locate keywords, addresses, or `FUN_XXXXXXXX`.


3. Once candidates are found, select only a single function or a small range.


4. Re-read original bytes from the current baseline and re-verify using `tools/disassemble_rom.py`.


5. Document the similarities and differences between the historical pseudocode and the current disassembly separately.


6. When evidence is insufficient, tag as `historical/static`, `inferred`, or `hypothesis`; patches must not be generated directly.



Example searches:

```text
Search address: 08013594
Search function: FUN_08013594
Search historical variable: DAT_03003580
```[cite: 1]
