# end_dungeon_on_death (CN baseline / English ROM)

New mod. Dying ends the dungeon run. The player is sent to town as usual (death animation, the
vanilla death drop, the inn wake-up scene, full heal), but **the Angel never comes** to offer
"Shall I take you back?". The gear and gold the death dropped are deleted, and the dungeon's
progress is cleared the same way the world map clears it when you forfeit a dungeon. The next
trip goes through the world map, which starts every dungeon from its first floor.

- Definition: `Patches/Definitions/Custom/end_dungeon_on_death.json` (stage `user_accepted`, 2026-10-28),
  generated by `Patches/end_dungeon_on_death/build.py` (checks every preimage).
- Ship: `Patch_Manager/patches/end_dungeon_on_death.bps` (69 B, SHA-256 `2e378fe0…`) and
  `Patch_Manager/patches/cn/end_dungeon_on_death.bps` (27 B, CN-compatible).
- Writes: `0x08088F7C` (4 B), `0x08089888` (4 B), code `0x080BC1C0` (20 B).
- **Allocation:** `0x080BC1C0..0x080BC1DF` (20 B used; was zero, no literal references, no other
  definition or shipped patch writes there). Owner `end_dungeon_on_death`.
- **Stacks with `lose_all_on_death`** (no shared bytes; both orders give the same ROM, SHA-256
  `729adb78…`). Together: dying deletes everything but the soul *and* ends the run.

## The patch

The Angel is a task (kind 1, `0x08064154`). Only the town-arrival scripts start it, through the
task spawner `0x08065DF0(player, 1)`, and only while flag bit 14 of `0x03003518` is set (see below):

| Hook | Script | When |
|---|---|---|
| `0x08089888` | `0x080897B4` (inn) | the wake-up after a death (mode-4 arrival). Every non-arena death takes this path (runtime-verified). |
| `0x08088F7C` | `0x08088E90` (town entry) | arriving in town by another entry while bit 14 is still set. Static only. |

Each `bl 0x08065DF0` becomes `bl 0x080BC1C0`, `forfeit()`:

```
push {r4, lr}
bl   0x0805DBC4   @ delete every ground item (16-entry list; seq counter back to 1)
bl   0x08058634   @ clear the per-area floor-state table world+0x1C8 (20 x 5 bytes)
bl   0x08058768   @ clear world+0x22C[10] and the 8-byte records at +0x160/+0x164 [10]
pop  {r4}
pop  {r0}
bx   r0
```

These are exactly the calls the world map makes after `area_change(dest, 1)` when you leave town
for a destination (`0x0800C2B2..0x0800C2BE`). That is what forfeiting a dungeon does. The rest of
the arrival script runs unchanged: the bed scene, the revive, and clearing bit 14 at `0x08089A14`.

## Runtime A/B (`runtime_verified`, English ROM)

`Tools/.venv/bin/python Patches/end_dungeon_on_death/test.py ROM…` uses the user's
`Savestates/About_To_Die.ss0`, visible input only. It dies, wakes in the inn, A through the
dialogue, walks out of the inn to the town square, and stops where the vanilla Angel lands.

| | English | English + mod | + mod + lose_all_on_death |
|---|---|---|---|
| Angel task (bit 21) | running from the wake-up on | **never** | **never** |
| Angel outside | flies in, lands next to the player | **absent** (only a villager walks by) | **absent** |
| Ground list in town | hand armour `5/46` and gold (map 2), town item (map 36) | **town item only** | **town item only** |
| world+0x1C8 dungeon rows | kept (`3`s, `1`s) | **cleared** | **cleared** |
| Owner records | 15 (one armour piece and gold dropped) | 15 | 1 (soul) |
| Wake-up, heal, walking | normal | normal | normal |

The town's own item (map 36) is re-added by the town map. Row 9 of the table (`+0x1F5..+0x1F8 = 1`)
is written again by the next map's loader (`0x08058668`); vanilla does the same after a forfeit.

A second check on vanilla, `Savestates/Quitting_Dungeon.ss0`: moving the world-map cursor to
Driazhek Desert and pressing A starts the desert at area 6, sub-map 0 (world+0x40 = 0). The death
in About_To_Die happened on sub-map 2. So "start fresh" is the world map's own behaviour, and with
no Angel the world map is the only way back.

**Not tested:** the second hook `0x08088F7C`. Also untested: a normal save after death followed by
a reboot. The mod only changes RAM that the normal save copies whole (world+0x70 → block P, and
the ground list via the baseline's pre-save hook), so a save after death stores the cleaned state.
**User-accepted 2026-10-28** (tested in Patch_Manager: "works perfectly").

## What the game does around death and the Angel (English ROM = CN baseline, traced)

- **Flags word `0x03003518`.** Helpers sit at `0x0800C4C8..0x0800C9F0`, in set / clear / test
  triples. The bits this work touched:
  - **bit 3**, "in town": test `0x0800C61C`, set `0x0800C62C`, clear `0x0800C63C`. Set by the
    area-0 case of the transition switch, cleared by every other area. Clearing it by hand in town
    freezes the player.
  - **bit 7**: test `0x0800C710`, clear `0x0800C6FC`. When set, the death drop is skipped (the
    drop gate checks `0x0800C8D0` and `0x0800C710`), and the inn takes a no-Angel branch at
    `0x0808985C`, which runs `0x08058450`, `0x0805AC64`, `0x08016408`, clear bit 7, then `0x08026714`.
    It looks like a special mode where death already ends the run. This mod doesn't use it, because
    it would also cancel the gear drop.
  - **bit 14**, "died, revive pending": test `0x0800C860`, set `0x0800C838`, clear `0x0800C84C`.
    The death task sets it at `0x08063D4C`. The inn script revives the player and clears it.
    The Angel task sets it again at `0x0806439A` (Angel declined / map left). Without it the
    player wakes with 0 HP and no body (tried: NOP at `0x08063D4C`).
  - **bit 21**, "Angel task running": set `0x0800C870` (at Angel task start, `0x08064216`), clear
    `0x0800C884`, test `0x0800C898`.
- **Death flow.** Lethal damage changes the life state. At `0x08011C68`, if not in town and not
  in the arena, the death point is saved:
  - player+0xAC/+0xB0 = x/y (set to −1 when player+0x38 bit 13 is set);
  - player+0x32 = `[0x030012A0]` (mode 2);
  - player+0x34 = `[0x0300129C]` (area);
  - then `0x08065DF0(player, 0)` starts the **death task** `0x08063C84`.

  The death task plays the animation (160 frames). In town (bit 3), it warps to
  (player+0x34, player+0x32), which is what the Angel's "yes" triggers. Otherwise, outside the
  arena, it calls `0x0805847C(0, 4)` and sets world+0x36 = 3. In the arena it calls
  `0x08026C0C(0xB, 0, 1)` instead.
- **Transitions.** `0x0805847C(area, mode)` → `0x08026C0C(area, mode, fade)`:
  - a switch on the area (table at `0x08026C50`) sets or clears bit 3 and sets world+0x71C to
    that area's entry script for the mode (town: table `0x084FE790`, mode 4 = inn bed);
  - then at `0x08026F56` it sets world+0x10 = 0, world+0x40 = mode and world+0 = area.

  world+0x40 is 2 in a dungeon, 4 after a death and 0 after a world-map pick. Forcing modes on the
  death call: 0 = town gate (the Angel still appears), 1–3 = various town interiors, 5 = crash.
- **World map.** `0x0800C212` calls `area_change(dest, 1)` (`0x08022D78`). That writes the area,
  zeroes world+0x40 and world+0xE..+0x21, then a per-area switch (24 cases) sets the return map
  world+0x8. For any destination other than town, the cleanup above runs next.
- **The Angel task** `0x08064154` starts at (184, 312) in town, flies to the player and holds the
  dialogue. It loops while bit 3 is set. When it ends it clears bit 21; when declined it re-sets
  bit 14. Its task stack in the user's states was at `0x020011A0..0x02001260`.
- **Map-state load switch** `0x08022724` (on world+0x70 = P+0): case 0/2 → `0x0802275C` (fresh,
  calls `0x08058634`/`0x08058768`), case 1 → `0x0802285C`, case 3 → `0x080228B8` (restores
  saved actors and ground items, then starts task kind 1 at `0x08022A48` unless world+4 bit 8),
  case 4 → `0x08022A52`. Case 3 isn't on the death path and isn't patched.
- **Task spawner** `0x08065DF0(arg, kind)`: kind 0 → `0x08063C85` (death task), kind 1 →
  `0x08064155` (Angel). Callers: `0x08011CC6` (kind 0), `0x08022A48`, `0x08088F7C`, `0x08089888`
  (kind 1).

## Test method notes

- Writes to the player actor survive map changes (the actor isn't rebuilt). So clearing
  player+0x32/+0x34 is a valid diagnostic. It didn't stop the Angel, because the Angel doesn't read
  those fields; it only uses them when it warps you.
- To find the Angel, the RAM was searched for its on-screen position (u32 pairs in 1/256 px). That
  landed in its task stack. The return address there named the task (`0x0806xxxx`), and the
  spawner's literal table named the kind.
- The walk from the inn bed to the town square, as `frames:KEYS` tokens, is in `test.py` (`WAKE`,
  `WALK`).
