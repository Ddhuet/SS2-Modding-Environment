# counter_fix_slash: COUNTER fix + a red slash on counter (test variant)

Definition: `patches/custom/counter_fix_slash.json`, generated by `python3 slash/build.py` from
`slash/src/counter_slash.s`. Patch: `Patch_Manager/patches/counter_fix_slash.bps` (English → English+mod,
557 B, sha256 `06791f8c…`). `slash/rebuild.sh` regenerates the definition, the `.bps` (from the Japanese
ROM via `english_translation.bps`) and the test ROM `translation/build/ss2-en+counter_fix_slash.gba`
(sha256 `4be4b4cc…`). Not in the web patcher yet (the user copies it after testing).

Stacked check: Japanese ROM + `english_translation.bps` + `respec.ips` + `counter_fix_slash.bps` gives
sha256 `5f015f96…` in both Patch_Manager and the web patcher's `patcher.js` (Node), and the slash
fires in that ROM too (same diagnostic run as below).

It contains the official `counter_fix` writes unchanged (`0x0801F1C0`, `0x0801F1C6`), so it
**replaces** `counter_fix`: don't stack the two (`combine_patch.py` refuses the overlap anyway).
The original `patches/definitions/counter_fix.json` is untouched.

## What it does

When a COUNTER lands, a 32×32 red diagonal slash OBJ is drawn over the target's position for
6 frames. It stays at the world position where the counter happened (it doesn't follow the enemy,
but it scrolls with the camera). It's drawn in OAM slot 0, so it's on top of everything.

## How (CN baseline = English ROM)

- **Counter site.** Damage routine `0x0801E358`, counter branch: gate `bl 0x0801DC54` (player
  class, `[[0x03003580]]+0x10`, must be 0 = Warrior), COUNTER level `[[0x03003580]]+0x54` ≠ 0,
  target state `[r8+0xC]` == 2 (attacking). The bonus damage is then computed and the counter
  sound plays: `movs r0,#0x27; bl 0x08059A8C` at `0x0801E654`. That 6-byte pair becomes
  `bl counter_hook; nop`. `counter_hook` stores the target's world pixel position
  (`[r8+0x14]>>8`, `[r8+0x18]>>8`), arms the timer, then plays the sound. r8 is the target actor.
- **Per-frame draw.** End of the field sprite builder `0x08008B18` (only caller `0x08001208`, the
  same call `enemy_hp_bars` hooks): `pop {r4}; pop {r0}` at `0x08008B2E` becomes `bl frame_hook`;
  `frame_hook` does those pops and returns. While the timer runs it:
  1. skips when outside field scenes (`[0x03002960]`==0), OAM full (`[0x03002954]`≥127), fewer than
     16 OBJ tiles left (`[0x03002958]`>0x3F0), copy queue nearly full (`[0x030023F8]`>398), or off-screen;
  2. queues 512 B of tiles from ROM to the next free OBJ tiles via the native copy queue `0x08001348`;
  3. sets OBJ palette 15 colour 1 to red (`0x001F`) in both PRAM and the game's palette buffer
     (`0x03001FE0`, OBJ half at `+0x200`; `0x030023C2`). Writing PRAM alone gets overwritten each
     vblank (the slash showed black). Palette 15 was all zero in every field state checked
     (5_Mobs, Angel_Wing, Warrior_Pathing);
  4. moves shadow-OAM slot 0's attrs 0–2 to slot n, writes the slash in slot 0, n += 1. attr3 (the
     affine parameters) stays in place.
  Screen position is the same transform `enemy_hp_bars` uses: world − camera (`0x0300328C/E`) −
  shake (`+8/+10`), then −16/−28 to centre the 32×32 on the body.
- Timer word: `0x534C0000 | frames`. Anything without the `0x534C` magic is idle, so uninitialised
  IWRAM can't draw a stray slash. Cost when idle: about 8 instructions per frame. When active it
  adds one 512 B queued copy per frame for 6 frames.

## Allocations

| Range | What |
|---|---|
| `0x080BB268..0x080BB3B3` (332 B, was zero) | Thumb code (`counter_hook`, `frame_hook`) + literal pool |
| `0x09013000..0x090131FF` (512 B, was zero) | 32×32 4bpp tiles, colour 1 |
| IWRAM `0x03007920..0x03007927` | timer/magic word, world x, world y. Free by the same evidence as enemy_pathing's `0x03007800` block: no code global above `0x030077B0`, the main stack never below `0x03007CDC` |
| OBJ palette 15, colour 1 | set to red while a slash is drawn |

## Checks

- `mod_conflicts.py --defs patches/custom`: ok. `combine_patch.py` with the 17 other official singles
  (without `counter_fix`) and every custom mod: no overlap.
- **runtime_verified (diagnostic setup):** user state `translation/build/Warrior_Pathing.ss0`
  (`2f12a658…`, Warrior, 5 enemies) on `ss2-en+counter_fix_slash.gba` (`4be4b4cc…`). It has COUNTER
  level 0, so the script makes one **diagnostic RAM write** (`[[0x03003580]]+0x54` = 1). Everything
  after that is visible input: `slash/counter_bot.py` walks toward the nearest enemy and, when one
  enters state 2 within ~60 px, faces it and presses A. Over 3000 frames, 4 counters fired
  (frames 472, 798, 912, 1026). Each armed the timer and drew the slash for 6 frames. It's visible
  from the frame after the hit, because hardware OAM updates at the next vblank
  (`docs/mods/evidence/counter_fix_slash_474.png`, `…_800.png`). Ordinary hits (target state 0/9)
  drew nothing.
- No user state has a Warrior with COUNTER learned and enemies on screen, so a counter without the
  RAM write is not_run.
- not_run: runtime stacking with `enemy_hp_bars` (both append to the same shadow OAM; this one runs
  first), boss fights, save/load (nothing saved), long sessions.
